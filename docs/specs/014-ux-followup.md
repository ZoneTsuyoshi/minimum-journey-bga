## 目的

作者の別のゲームが BGA の Public Alpha 審査で UX の指摘を受けた（2026-11-28 に作者から共有。要旨は下の「参考にした審査指摘」）。作者から「同じ指摘を受けないか点検して」と頼まれ、2026-11-28 の `main` を点検した。その結果、このゲームにも、ツールチップ（拡大表示を含む）、左に浮いたジャンプリンク、準備場の入れ子の横スクロールの不具合が見つかった。この仕様書は、それらの原因と直し方を、実装者がこの仕様書だけを読めば実装できる粒度で決める。承認後、別の PR（I-20・I-21）で実装し、作者が Studio で確認してから Public Alpha を再申請する。

## スコープ

- 対象: 拡大表示（位置・大きさ・タッチ操作）、ブラウザ標準の `title` 属性のツールチップの置き換え、ジャンプリンクの廃止、046 の組の配置と準備場の横スクロールの廃止、軽微な見た目の統一（2 点）、検証方法（プレビューの改修と自動チェック）、実装の分け方。

## 記法と調査の前提

- 記法は 013 と同じ。**【確認】** は公式ドキュメント（または公式 PDF）で確認した事実、**【実測】** は本タスクで実際に計測した値、**【提案】** は本仕様書の提案（数値はプレビューで調整してよい基準値）、**【推定】** は実測できず推定した値、**【未確認】** は確認できなかった事項。コードの事実は「ファイル名:行番号」で示す（2026-11-28 時点の `main`）。
- 調査日は 2026-11-28。実測はローカルのプレビュー（`scripts/preview/`。Chrome のヘッドレス、Playwright）で行った。プレビューは BGA の実物と次の点が違う。BGA の実物での確認は作者に頼む（§9.3）。

## 参考にした審査指摘

作者の別のゲームが受けた Public Alpha 審査の指摘（2026-11-28 に作者から共有）の要旨。同じ指摘を受けないかを点検する物差しとして使う。

1. 全体の構造: 大きな角丸の箱、浮いたボタン、ばらばらの情報欄、不統一なスタイルで、卓上ゲームの翻案でなくアプリのように見える。
2. ツールチップ: 一部の情報が正しく表示されない。読めること、正しい位置、画面内に収まること、マウスとタッチの両方で使えること。重要な盤面要素を不必要に隠さないこと。
3. 上部の大きなセットアップ／フェイズ表示が場所を取り、情報が重複する。部品と説明・副次的な操作を区別する。
4. プレイヤーの領域: 盤面の下のカードと詳細情報の階層を明確に。コンパクトな情報は BGA 標準のプレイヤーパネルに置き、重複させない。
5. 見た目の一貫性と部品の読みやすさ。カードの文字が小さく、過度な拡大なしで読めること。
6. 左の浮いたボタンが画面から切り離された要素として振る舞い、スクロール時に BGA のフッターに重なる。デスクトップ・ワイド・モバイルを確認し、不要な入れ子のスクロールバーを避ける。
7. 操作の分かりやすさ: 使える操作・置ける先・選んだ部品を、追加の説明文より一貫した強調と文脈のフィードバックで伝える。

挙げられたガイドラインの節: A.1、A.2、A.3、A.5、B.1、C.2、C.4、E.1、E.3。

### 2. 拡大表示（A・B・C。009 §9.5 の変更）

**【確認】** B.1: ツールチップは「役に立つ情報」で、小さくて読めない部品の文字や記号を拡大して見せる手段でもある。手本（Altered）はカードの横に拡大を出している。同じ情報を同じ形で 2 度出すことは避ける（UxPdf B.1）。Mobile: 必須の情報をホバーだけで見られるようにしない。タッチで使える代わりを用意する。

拡大表示の構成（現状のまま）: 大きなカード画像（`#mj-zoom-img`）と英語の効果文（`#mj-zoom-text`）。`body` 直下の `#mj-zoom`（`position: fixed`）。マウスのホバー 400ms（`scheduleZoom(cardEl, 400)`）、タッチの長押し 500ms、選べないカードのタップで開く。

#### 2.1 マウス: 位置の決め方（B）

ホバーしたカードの矩形（`cardEl.getBoundingClientRect()`。以下 R）と重ならない位置に出す。

1. 使える縦の範囲: 上端 `minTop` = `max(8, #page-title の下端 + 8)`、下端 `innerHeight − 8`（現状どおり。`Game.js:2624-2630`）。ステータスバーに重ならない。
2. 横の位置: 次の順で、最初に収まるものを使う。ここで W は拡大表示の幅（§2.2 で決める）、`viewWidth` は `min(innerWidth, documentElement.clientWidth)`。
   - 右: `left = R.right + 8`、条件 `left + W ≤ viewWidth − 8`
   - 左: `left = R.left − 8 − W`、条件 `left ≥ 8`
   - どちらも入らないとき: 空きの広い方の側に出し、W をその空きに収まるまで縮める（§2.2 の下限 W_min まで）
   - それでも入らない（`viewWidth` が R の幅＋2×(W_min + 16) 程度より狭い。マウスでは通常起きない）とき: カードの上か下の、空きの広い方に出す。縦にも入らなければ重なってよい（読めることを優先）
3. 縦の位置: 拡大表示の中心をカードの中心に合わせ、`[minTop, innerHeight − 8 − 高さ]` に収める。
4. 隣のカードや探査山札を覆うことは、カードの横に出す以上避けられない（今回は許す）。ただし、ホバーしたカード自身は常に見える。
5. 遅延（400ms）、`pointer-events: none`（マウスで開いたときは維持してよい。マウスが拡大表示の上へ動いて `pointerout` で閉じる、という循環を避けるため）は現状のまま。
6. 開いている間にページがスクロール・リサイズ・回転したら閉じる（拡大表示は `position: fixed` でカードから離れてしまうため）。`scroll`（capture。ただし拡大表示の中のスクロールは除く）、`resize`、`orientationchange` で `hideZoom()`【提案】。

#### 2.2 寸法: 英文を切らない（A）

**【実測】** 現状の幅の決め方 `--mj-zw = max(140px, min(360px, 90vw, (avail − 120px) × 500/699))` では、1366×768（`avail` = 768 − 116 − 8 = 644px）で画像の高さが 503px（幅 360px）、英文に残るのが 141px になる。英文は 218px 必要（最長の 043。幅 360px）。ここから、英文の高さは固定の 120px でなく、**測って**決める。

決め方【提案】。`showZoom` で次の順に決める（数値は基準値。プレビューで調整してよい）。

| 段階 | 条件 | 結果 |
| --- | --- | --- |
| 1. 英文の高さ Ht を測る | 拡大表示を画面外（`visibility: hidden`、`left: -9999px`）で出し、候補の幅で `#mj-zoom-text` の `scrollHeight` を読む | Ht（043 で約 218px） |
| 2. 縦並び（画像の下に英文） | `zw = min(360, 90vw, (avail − Ht) × 500/699)` が **zw ≥ 220** | 縦並び。画像の幅 zw、英文の欄の幅 `max(zw, min(280, 94vw))`。英文は全部見える（欄の高さ = Ht） |
| 3. 横並び（画像の左に英文） | 2 で zw < 220（画面の高さが低い。Ht = 218 なら `avail` < 約 526px） | 画像の幅 `zw = min(300, avail × 500/699)`。英文の欄は画像の右に置き、幅 `min(320, viewWidth − 16 − zw − 8)`（下限 240）。この幅で Ht を測り直す |
| 4. それでも入らない | 3 で Ht（測り直した値）> `avail` | 英文の欄だけを `overflow-y: auto` で縦スクロール可にする。タッチは §2.3 のとおり `pointer-events: auto` でスクロールできる。マウスは `pointer-events: none` なので、文字を 12px にして収める（ここまで低い画面は `avail` < 約 280px。ウィンドウの高さ約 400px 未満で、マウス操作では通常起きない。切れるのを許す） |

根拠（**【実測】** と上の式からの計算）:

| 画面 | `avail` | 現状: 画像／英文の見える高さ | 提案: 画像の幅 zw／画像の高さ／英文 |
| --- | --- | --- | --- |
| 1280×800（マウス） | 676px | 画像 503px（360px 幅）／173px | 328px／459px／218px（全部見える） |
| 1366×768（マウス） | 644px | 503px／141px | 304px／425px／218px（全部見える） |
| 390×844（タッチ） | 693px（203 + 490 から逆算した **【推定】**） | 490px（351px 幅）／203px | 339px／474px／218px |
| 1440×900、1920×1080 | 752px 以上 | 全部見える | zw = 360px（上限）で変わらない |

- 画像の幅が 360px から約 300px に縮む画面がある（1366×768）。カードの本体は 120px で表示されており、300px でも 2.5 倍。効果文は拡大表示の英文でも読めるので許す。
- 「Tap the card to select it」の行（タッチで、選べるカードのとき）が加わるので、Ht は測って決める（固定値にしない）。
- 数値の定数（220、300、320、240、8）は `Game.js` の定数にまとめ、CSS の `--mj-zw` は JS が `style.setProperty` で入れる（現在の `calc` による決め方をやめる）。縦並び・横並びは `#mj-zoom` の `data-mj-zoom-layout="stack|side"` で切り替える。
- 変更する CSS: `.mj-zoom`（`minimumjourney.css:855-875`。`--mj-zw` の `calc` を削除、`flex-direction` を `data-mj-zoom-layout` で切り替え）、`.mj-zoom-text`（高さの上限を `avail` に）。

#### 2.3 タッチ: 閉じるタップを下に通さない（C）

現在の流れ（`Game.js:2545-2568`）は設計として正しいが、判定が効かないのと、イベントを止めないのが原因。

**【確認】** BgaCards の選択は、カードのストック要素に付けた `click` リスナー（バブリング）で起きる（配布物 `bindClick`）。`pointerdown`・`touchstart` では起きない。したがって `document` の capture の `click` で止めれば、下のカードの選択は起きない。

直し方【提案】:

1. **選べるかの判定を直す。** 判定関数 `isSelectableCard(cardEl)` を作り、`cardEl.matches('.mj-selectable') || cardEl.querySelector('.mj-selectable') !== null`（カード本体またはその子孫の面に付いているか）とする。`Game.js:2559`（click ハンドラ）、`Game.js:2620`（`showZoom`）の 2 か所をこれに置き換える。選択済み（`mj-selected`）のカードにも、選べる状態を表す `mj-selectable` の面は残る（BgaCards の `setSelectableCard` と `selectCard` は別のクラスを切り替える）。
2. **閉じるタップはその場で消費する。** 拡大表示が開いている間の capture の `click` では、最初に `event.preventDefault(); event.stopPropagation();`（`stopImmediatePropagation` でもよい）を呼んでから、次の分岐に進む。
   - 拡大表示の上のタップ、かつ拡大したカードが選べる（`zoomCard !== null`）: 拡大表示を閉じ、そのカードを選ぶ（`zoomCard.click()`。このときだけイベントを再発行するので、二重にならないよう上の消費の後に行う）
   - 拡大表示の上のタップ、選べないカード: 閉じるだけ
   - 外側のタップ: 閉じるだけ（どの要素にも届けない）
3. **長押しの指を離したときの click を無視する。** 長押し（500ms）で拡大表示が開いたあと、指を離すと `click` が出ることがある（**【未確認】** 端末による）。拡大表示を開いてから 400ms 以内の `click` は無視する（`zoomOpenedAt` を記録）【提案】。
4. **選べるカードの単発タップ**は拡大表示を開かない（現状の設計どおり。判定が直るので、探査の選択処理だけが動く）。長押し（500ms）で開き、拡大表示に「Tap the card to select it」を出す（`Game.js:2621-2622` のまま）。
5. **タッチで開いたときは拡大表示を `pointer-events: auto` にする**（`data-mj-pointer="touch"` などで CSS を切り替える）。これで英文の欄をスクロールできる（§2.2 の段階 4）。拡大表示の中のスクロールでは閉じない（click は発生しない。§2.1 の `scroll` で閉じる処理から除く）。マウスで開いたときは `none` のまま。
6. 山札一覧（`.mj-pile-modal`、`body` 直下）の中のカードも、同じ操作で拡大する（現状のまま。`setupZoom` の対象。山札一覧のカードは選べないので、タップで開き、タップで閉じる）。拡大表示の `z-index`（2000）は山札一覧（1900）より前（現状のまま）。

#### 2.4 マウスとタッチが混在する端末

開くときの `pointerType`（`lastPointerType`。現状 `Game.js:2570-2590`）で、その拡大表示がマウスかタッチかを決める。マウスで開いたものはマウスの規則（§2.1、`pointer-events: none`）、タッチで開いたものはタッチの規則（§2.3）。開いている間に切り替わった場合（マウスで開いたあとタップした）は、タップを「閉じる」として消費する（タッチの規則）。
