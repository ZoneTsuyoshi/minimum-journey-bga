## 目的

準備フェイズで 2 人以上が同時に「ドロー」した回は、ドローした各プレイヤーが引いたカードの【ドロー時】効果を解決する。ドロー時効果には互いに干渉するものがあるが、複数人が同時に引いたときの解決順は紙のルールブックに書かれていない。この仕様書は、作者回答「互いに影響する効果は優先度をつける想定」に沿った**優先度体系**を定める。

第4回の作者回答（2026-10-13）で、案 A（6 段階）が大枠で了承され（D1）、054 の独立化（D2）、P5 の区分（D3）、同優先度の処理順（D4・D5）などの修正が示された。本書はそれを反映した版で、**確定した部分と、まだ提案・未確定のままの部分が混在している**。文中では次の印で区別する。

| 印 | 意味 |

| 【カード文面】 | カードの効果テキストにそのまま書かれていること（解釈を足していない） |

## スコープ

- 対象: 同じ回に複数人が引いたドロー時効果の解決順（優先度）、同優先度の扱い、解決手順、検証例、BGA 実装への申し送り
- 対象外: 各カード単体の効果解釈（002 の未確定事項で扱う）、準備フェイズ全体の流れ（001 §5）、BGA の状態遷移・通知の詳細設計（T-006 / T-008）

読み取り方:

- 行 A（抑止）は、作用先が「ドロー時効果を持つカードの効果」全般なので、列 B〜F すべてに影響する。これが優先度の上位に置く理由の根拠となる。ただし 054 だけは例外で、抑止されない（D2）。

### 5. 同じ優先度の効果が複数あるときの規則

#### 5.1 規則（確定）

【確定】D3・D4・D5・D8:

1. **他プレイヤーに影響を与えない効果は、全員同時に処理する**（D5）。P5-同時、P6 がこれに当たる。
2. **他プレイヤーに影響しうる効果は、同優先度の中で順番に処理する**（D3）。D3 が明示したのは P5 の探査場の列の選択（007、008 で 007 をコピーした場合）。
3. **順番に処理する場合の順序は「お守りから遠いプレイヤーから反時計回り（お守り保持プレイヤーが最後）」**（D4）。式で書くと、プレイヤー p の距離 d(p) を「お守り所持者から BGA の席順（D10）の時計回りに数えた人数（所持者 = 0）」としたとき、**d(p) の大きい順**に処理する。所持者が最後になる。探査手番の第3条件（所持者が最優先）とは逆向きである。
4. D4 は「同優先度の処理は」と一般に述べているので、**順番に処理する必要がある同優先度の効果すべてに適用する**（P1〜P4 を含む）。ただし D8 により各カードは 1 枚ずつしか存在しないので、実際に同優先度で順番の問題が生じるのは P5-順番（007 と 008 のコピー）に限られる。P1（039 と 053）は F3 が結果を順序に依存しない形で定めているので、順序を用いない。P2（043）の実行順は、別々の山札を対象とするので結果に影響しない。
5. **F3 は一般則**（D8）: 同優先度の抑止効果は互いに無効にし合い、それでも各自の抑止作用は残る。同名カード同士の重なり（053 + 053、039 + 039 など）は起こりえない。

#### 6.1 手順

    D = [c for c in drawn_cards if c.has_on_draw_effect]

    # P0: 054（他のカードの影響を受けない。D2）

        # passes(039, c) = VIRGO in c.symbols
        # passes(053, c) = (c.owner == f.owner)  ※053 自身も他の抑止カードの条件で判定される

    pods = [c for c in D if c.id == 043 and c.valid]
    decisions = collect_decisions({y: "戻すか" for y in players_with_drawn_card if exists(p in pods where p.owner != y)})
    for y in decisions where decisions[y] == "return":
        return_card_to_deck(y.drawn_card); shuffle(y.deck)
        y.prepare(1, effect_fires = false)                  # D7
        D.remove(y.drawn_card)                              # 抑止の判定結果は取り消さない

    # P3: 他プレイヤーへの追加準備
    for c in D where c.id == 024 and c.valid:
        for z in players_already_finished: z.prepare(1, effect_fires = false)
        # 054 による強制ドローの回では、準備終了は打ち消されているので players_already_finished は空（N38）

    # P4: 探査場の入れ替え
    for c in D where c.id == 036 and c.valid: resolve(c)

    # P5-順番: 他プレイヤーに影響しうる効果は順番に（D3、D4）
    for c in order_by_amulet_owner([c for c in D if c.is_laser_select and c.valid]):   # 007、007 をコピーした 008
        resolve(c)
    # P5-同時: 自分にしか影響しない効果は全員同時（D5）
    resolve_simultaneously([c for c in D if c.level == P5 and not c.is_laser_select and c.valid])

    # P6: 次の準備選択の制約を記録（全員同時。D5）
    for c in D where c.level == P6 and c.valid: record_next_choice(c.owner, c)

#### 6.4 任意効果と非公開情報

- 「してもよい」を含む効果（009、014、020、035、036、043、050 など）は、持ち主だけが選択する。選択しなかった場合の工程（シャッフルを行うか）は 001 §11・Q-28 に従う。

### 8. BGA 実装への申し送り

実装の詳細には踏み込まない。T-006（状態遷移）と T-008（カード効果）が参照する前提を示す。

1. **優先度をカード定義のデータ項目として持つ【提案】**: 002 のカード定義に「ドロー時効果の優先度」（0〜6 の整数、ドロー時効果を持たないカードは空）と「同優先度内の処理区分」（順番／同時）を追加する。各カードの値は §4.1 の表のとおり（054 は 0、007 は 5 の順番、005 などは 5 の同時、028・029・049 は 6）。008 のみ「コピー元の優先度を継承」を示す値にする。これにより、解決手順（§6.1）はデータ駆動で書ける。
