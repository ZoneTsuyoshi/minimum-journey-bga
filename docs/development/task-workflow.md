# タスクの進め方

Claude Code を使った開発の進め方です。メインエージェントが全体を統括し、個々のタスクはサブエージェント（sonnet）に委託します。

## 役割分担

| 役割 | 担当 | 内容 |
| --- | --- | --- |
| ユーザー（作者） | 人 | ルールの最終判断、仕様書・PR の承認、マージの可否、BGA Studio / GitHub の設定 |
| メインエージェント | Claude Code 本体 | タスク分解、ワークツリー作成、サブエージェントへの指示、成果物のレビュー、PR 作成、後始末 |
| サブエージェント | sonnet | 指定されたワークツリー内での仕様書作成・実装・コミット |

## タスクのライフサイクル

タスクは「仕様」と「実装」の 2 段階に分け、それぞれ別の PR にします。

### 1. 仕様フェーズ

1. [../tasks.md](../tasks.md) からタスクを選び、状態を「仕様作成中」にする。
2. メインエージェントがワークツリーを作成する（[git-workflow.md](git-workflow.md) 参照）。

   ```bash
   git worktree add .worktrees/spec-NNN-<slug> -b docs/spec-NNN-<slug> origin/main
   ```

3. サブエージェント（sonnet）に仕様書の作成を委託する。成果物は `docs/specs/NNN-<slug>.md`。
4. メインエージェントが差分をレビューし、ルールブックとの食い違いや未確定事項を確認する。
5. PR を作成し、ユーザーがレビュー・承認する。
6. マージ後、ワークツリーとブランチを削除する。

### 2. 実装フェーズ

1. 仕様書がマージ済みであることを確認し、タスクの状態を「実装中」にする。
2. 新しいワークツリーを作成する。

   ```bash
   git worktree add .worktrees/<slug> -b feat/<slug> origin/main
   ```

3. サブエージェント（sonnet）に、仕様書を根拠とした実装を委託する。
4. メインエージェントが差分と lint の結果を確認し、PR を作成する。
5. ユーザーの承認後にマージし、ワークツリーとブランチを削除する。
6. タスクの状態を「完了」にする。

ドキュメントの軽微な修正など、仕様書を必要としない変更は実装フェーズのみで構いません。

## サブエージェントへの指示

サブエージェントは会話の文脈を引き継がないため、指示だけで作業が完結するように書きます。

指示に必ず含める項目:

- **目的**: 何のためのタスクか、完成するとどうなるか
- **作業ディレクトリ**: ワークツリーの絶対パス（この外のファイルは変更しない）
- **読むべき資料**: ルールブック、カード画像、関連する仕様書、`CLAUDE.md`
- **成果物**: 作成・変更するファイルのパス
- **やらないこと**: スコープ外の作業、`data/` の変更、push や PR の作成（メインエージェントが行う）
- **完了条件**: 何が満たされれば完了か、報告に含めてほしい内容（未確定事項、判断に迷った点）

運用上の注意:

- Agent ツールを `model: "sonnet"` で起動する。
- Agent ツールの `isolation: "worktree"` は使わない。ワークツリーの場所が `.worktrees/` 配下にならないためで、メインエージェントが事前に `git worktree add` で作成する。
- 互いに依存しないタスクは、別々のワークツリーで並列に委託してよい。同じファイルを触るタスクは直列にする。
- サブエージェントの完了報告はそのまま信用せず、メインエージェントが `git diff` で内容を確認する。
- ルールブックに書かれていない挙動をサブエージェントが推測で埋めていないか確認し、未確定事項はユーザーに質問する。

## 仕様書の書き方

- ファイル名は `docs/specs/NNN-<slug>.md`（`NNN` は 3 桁の連番）。
- [../specs/_template.md](../specs/_template.md) をコピーして作成する。
- 作成したら [../specs/README.md](../specs/README.md) の一覧に追記する。
- 根拠（ルールブックのページ・節、カード番号、BGA 公式ドキュメントの URL）を明記する。
- 判断がつかない点は「未確定事項」にまとめ、推測で確定させない。
